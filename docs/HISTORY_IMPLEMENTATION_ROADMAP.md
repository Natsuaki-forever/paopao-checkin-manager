## 5. 已遇到的问题与处理结论

### 5.1 “另一个签到任务正在运行”

原因：

- 当前 `CheckinRunEngine` 使用进程内全局 `running` 布尔锁。
- “立即运行”接口会同步等待整个任务结束。
- 页面访问超时或重试期间再次点击，会显示“另一个签到任务正在运行”。

当前状态：

- 锁会在 `finally` 中释放，不是永久死锁。
- 仍需改成持久化任务队列，见阶段 Q。

### 5.2 论坛手动登录后，自动任务仍出现验证码

原因：

- 用户手动登录发生在本地浏览器。
- 自动任务运行在阿里云服务器的全新无痕 Playwright Context。
- 两者的 Cookie、localStorage、IP 和浏览器指纹完全不同。
- 当前每次运行都创建新 Context，没有加载持久会话。

正确方向：

- 为每个任务保存加密的 Playwright `storageState`。
- 优先复用会话访问签到页。
- 失效时通知人工更新。
- 第一阶段可支持 Cookie 导入。
- 已提供服务器端一次性人工登录会话提交令牌：10 分钟有效、仅可使用一次，服务端只保存令牌哈希和加密会话。

### 5.3 登录后页面已进入后台却被判失败

原因：

- SPA URL 先变化，登录组件稍后卸载。
- 原逻辑只等待 2 秒并立即检查密码框。

处理：

- 已实现 30–60 秒等待、路由稳定判断和高级成功标志。
- 相关测试已通过并部署。

### 5.4 目标站点登录地址超时

原因：

- 阿里云服务器直连目标站点失败。

处理：

- 使用 `http://mihomo:7890`。
- 代理访问已经实际验证为 HTTP 200。

### 5.5 系统设置页找不到保存按钮

原因：

- “保存设置”只位于系统设置页面顶部右侧。
- 代理区域只有“检测配置”，容易误以为不能保存。

后续改进：

- 在代理区域增加“保存并检测”。
- 页面离开前提示存在未保存修改。

### 5.6 应用内浏览器偶发超时

- 浏览器连接正式域名时偶发超时。
- 不要因此反复重启线上服务。
- 可先使用域名健康接口、静态资源哈希、容器日志和本地 Playwright 夹具验证。
- 如果浏览器插件可用，仍应优先用它完成最终界面验收。

### 5.7 Windows 补丁工具故障

- 当前桌面线程中 `apply_patch` 可能因 Windows 沙箱辅助进程错误 1223 失败。
- 首选仍是 `apply_patch`。
- 只有明确确认工具故障后，才使用带目标片段校验的精确文本替换。
- 每次替换后必须运行类型检查和测试。

### 5.8 本地 Node/npm 路径

- 普通 PowerShell 可能找不到 `node`、`npm` 或 `git`。
- 使用 Codex 工作区依赖工具获取 bundled Node 路径。
- 不要使用 pnpm 自动迁移现有 npm 项目；曾导致 `node_modules/.ignored` 和临时 pnpm 清单。
- 正式构建仍以 `package-lock.json + npm ci` 为准。

## 6. 对 QD 项目的研究结论

参考项目：<https://github.com/qd-today/qd>

值得吸收：

1. 模板与账号任务分离。
2. 多步 HTTP 请求流程。
3. 变量替换、响应提取和成功断言。
4. Cookie 与运行变量持久化。
5. Queue Worker 和延迟重试。
6. 每任务代理和代理规则。
7. 通知条件、连续失败通知和批量汇总。
8. HAR 导入、步骤测试和整体测试。
9. 请求次数、循环时间和响应体限制。

不应照搬：

1. 任意 Python、JavaScript 或完整 Jinja 表达式执行。
2. 公共模板市场和多用户注册。
3. 自动破解验证码。
4. OCR 依赖。
5. 关闭 TLS 证书验证。
6. 未经过滤地执行 HAR 中的 URL、Cookie 和 Authorization。

目标不是复制 QD，而是形成：

```text
简单管理界面
  + 浏览器模板
  + HTTP 流程模板
  + 持久会话
  + 安全队列与通知
```

## 7. 原子级实施路线

每个编号应当是一个可独立提交、测试和回滚的修改单元。

### A. 安全与诊断基础

- A01：固化当前 v2 数据库与 28 项测试基线。
- A02：增加 queue/session/http-flow 功能开关，默认关闭。
- A03：运行记录增加 phase：queued/login/checkin/notify。
- A04：记录最终 URL 和判定信号，不记录敏感值。
- A05：建立统一敏感字段脱敏器。
- A06：建立 URL 安全检查，拒绝 localhost、内网和云元数据地址。
- A07：验证每次 HTTP 跳转和浏览器主文档跳转。
- A08：增加响应体、跳转次数、单步和总时长限制。

验收：所有开关关闭时，线上行为与当前版本一致。

### Q. 持久化任务队列

- Q01：数据库 v3 新增 `run_jobs` 表。
- Q02：支持 queued/running/succeeded/failed/cancelled。
- Q03：同一任务仅允许一个活动 Job 的部分唯一索引。
- Q04：保存排队、开始、心跳和完成时间。
- Q05：实现 Job Repository 单元测试。
- Q06：立即运行改为返回 HTTP 202 和 `jobId`。
- Q07：增加 `GET /api/jobs/:id`。
- Q08：增加单进程 Worker，初始并发仍为 1。
- Q09：重复点击同一任务返回已有 Job。
- Q10：启动时处理残留 running Job。
- Q11：调度器改为入队。
- Q12：增加排队任务取消接口。
- Q13：任务页面显示排队、登录、签到和通知阶段。
- Q14：前端轮询 Job，完成后刷新记录。

验收：两个不同任务可以排队；页面刷新后仍能看到状态。

### S. 浏览器会话持久化

- S01：数据库 v4 新增 `task_sessions`。
- S02：加密保存 Playwright `storageState`。
- S03：使用任务 ID 作为 AES-GCM 附加认证数据。
- S04：API 只返回会话状态和更新时间。
- S05：适配器允许输入已有会话。
- S06：创建 Context 时加载会话。
- S07：先访问签到页判断会话是否有效。
- S08：会话失效后回退账号密码登录。
- S09：登录成功后保存新会话。
- S10：挑战或失败时不覆盖旧会话。
- S11：增加 session_expired 状态。
- S12：任务列表显示有效、失效、未创建。
- S13：增加“清除会话”接口和按钮。
- S14：增加 Cookie 字符串导入。
- S15：校验 Cookie 域名并加密保存。
- S16：会话失效时通知人工更新。
- S17：服务器侧一次性人工登录会话提交令牌已实现；令牌 10 分钟有效且仅可使用一次。

验收：同一测试站点第一次登录，第二次不再进入登录页。

### P. 每任务代理

- P01：任务增加 inherit/direct/custom 模式。
- P02：旧任务迁移为 inherit。
- P03：指定代理凭据加密保存。
- P04：执行器解析任务最终代理。
- P05：检测代理访问目标网站，而不只是检测端口。
- P06：代理失败使用独立状态。

### T. 模板与任务分离

- T01：新增真正的 `adapterId`，逐步替代当前执行器含义的 `templateId`。
- T02：继续兼容旧 API 字段。
- T03：数据库 v5 新增 `templates` 表。
- T04：任务增加模板 UUID。
- T05：每个现有任务自动迁移为一个私有模板。
- T06：模板增加版本、名称和更新时间。
- T07：增加模板 CRUD。
- T08：新增“执行模板”页面。
- T09：添加任务时选择模板。
- T10：支持复制和保存新版本。
- T11：导出模板时排除账号、密码和会话。
- T12：预置通用网页登录、论坛签到骨架。

验收：一个模板可创建两个不同账号任务。

### H. HTTP 流程执行器

- H01：定义 `HttpFlowTemplateV1` JSON Schema。
- H02：支持 GET/POST/PUT/PATCH/DELETE。
- H03：支持 URL、Query、Header、Body。
- H04：只支持简单 `{{variable}}` 替换。
- H05：区分普通变量与秘密变量。
- H06：按顺序执行步骤。
- H07：步骤间共享 Cookie Jar。
- H08：持久保存 Cookie。
- H09：支持状态码断言。
- H10：支持正文包含/不包含断言。
- H11：支持 JSONPath 提取。
- H12：支持响应头和 Cookie 提取。
- H13：支持受限正则提取。
- H14：每一步保存脱敏摘要。
- H15：支持任务代理。
- H16：限制单步时间、总时间和响应体。
- H17：明确禁止 eval、JS、Python、完整 Jinja 和循环。
- H18：增加步骤编辑器。
- H19：增加单步测试。
- H20：增加全流程测试。

验收：本地两步登录+签到夹具能提取 CSRF、保持 Cookie 并通过断言。

### R. HAR 导入

- R01：限制文件大小。
- R02：服务端校验 HAR JSON。
- R03：默认过滤图片、字体、统计和静态资源。
- R04：列出请求供用户人工选择。
- R05：识别 Cookie、Authorization、密码并转为秘密变量。
- R06：默认删除响应正文。
- R07：转换为 HttpFlowTemplateV1。
- R08：建议 Token/CSRF 提取规则，但必须人工确认。
- R09：导入后先测试，不能直接启用。
- R10：导出不得包含秘密值。

### N. 重试与通知

- N01：失败分类为 network/proxy/challenge/auth/page/assertion。
- N02：网络失败采用 1、10、30 分钟延迟重试。
- N03：验证码和登录失败不自动重试。
- N04：页面变化最多重试一次。
- N05：重试重新入队，不占用 Worker。
- N06：页面显示下次重试时间。
- N07：每任务配置手动/定时、成功/失败通知。
- N08：支持连续失败 N 次通知。
- N09：成功后清零连续失败计数。
- N10：增加每日汇总。
- N11：后续增加 Bark、Telegram、自定义 Webhook。
- N12：通知失败不能改变签到结果。
