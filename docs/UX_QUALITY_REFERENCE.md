# 炮炮签到站：长期 UX 质量参考

更新时间：2026-07-13

本文用于后续界面修改前的质量校准。旧的 `0.7.0_UX_REDESIGN_PLAN.md` 是一次性实施计划，已完成并部署；可复用的视觉、交互和验收规则已沉淀到本文。

## 设计定位

炮炮签到站是签到任务控制台，不是营销落地页、游戏 HUD 或装饰型 Bento 展示页。

界面应满足：

- 普通用户能直接理解当前任务、异常和下一步动作。
- 管理员能快速定位用户、任务、会话、运行记录和系统状态。
- 文案短、明确、少解释，不使用第一人称。
- 视觉有品牌感，但不牺牲密度、可读性和可维护性。
- 自动执行相关页面优先表达安全、状态和可回退，不制造“已确认”的假象。

## 布局与响应式基线

每次涉及布局、登录页、表单、状态卡、导航或弹窗的改动，至少检查：

- `390px`：移动端安全边距、抽屉导航、无横向溢出。
- `1280px`：常见笔记本宽度，主内容不拥挤。
- `3840px`：宽屏重心不偏移，内容不贴边。
- 浅色与深色主题都要检查，不能只看默认主题。

登录页宽屏应使用居中约束的双栏整体，而不是让登录卡片跟随视口贴到右侧。左侧视觉和右侧表单要作为一个整体居中。

表单行内输入框、单位后缀和按钮必须有稳定网格间距；窄屏下自然换行，禁止贴边、共用边线或边框重叠。

## 登录页与小猪视觉

登录页左侧圆框应保持正圆，作为屏幕上的品牌视觉装置，感觉接近“圆框舞台”而不是普通占位图。

小猪可以有较大视觉尺寸，但必须满足：

- 保留明确留白，不挤压标题、输入框、按钮或移动端安全区。
- 位置与状态有关，不能随意贴边或遮挡信息。
- 像素小猪的方形轮廓、护目镜、圆润比例和轻微机械感可作为风格参考，但不能直接复刻旧图。
- 小猪可以承担状态情绪：登录招手、密码聚焦捂眼、注册爱心眼、管理员入口墨镜。
- 静态品牌标识仍是日历图标与“炮炮签到站”，小猪不替代正式 Logo。

彩蛋类小猪只能作为隐藏触发后的短动画，不应常驻侧栏、页脚或主工作区。

## 主题与颜色

深色主题不能只反转背景。所有局部容器必须使用主题 token，不要硬编码白底或浅色断层。

重点检查这些组件：

- 输入框和输入单位后缀。
- 通知预览。
- 提示框。
- 状态卡。
- 标签和小按钮。
- 弹窗、下拉菜单、抽屉导航。

状态色语义统一：

- 成功、健康、已完成：绿色。
- 明确失败、直接错误：红色。
- 待处理、需要验证、取消、页面变化、已签到或需确认：黄色或警示色。

零值不使用错误或警示色；例如“需要处理”为 `0` 时使用中性灰，只有存在待处理项才显示警示颜色。

不要让普通正文色承担状态含义，也不要只靠小圆点表达结果。

## 信息架构

登录后默认进入“运行总览”。第一屏优先回答：

- 今天计划执行多少任务。
- 已完成多少。
- 当前有什么需要处理。
- 下一项任务何时执行。
- 有多少有效会话。

侧栏按用途分组，账号入口只保留在右上角。不要在侧栏重复显示用户、账号页或退出入口。

移动端使用顶部栏和抽屉导航，不新增底部导航，避免主工作区被压缩。

## 表单与任务流程

添加和编辑任务优先使用分步流程：

1. 目标与模板。
2. 账号与识别。
3. 计划与通知。

每一步单独校验，错误靠近字段显示。返回上一步不能丢失内容。关闭存在未保存内容的流程时，使用站内确认弹窗，不使用原生浏览器确认框。

帮助文字贴近具体输入项，说明去哪里取得 Key、Webhook 或 HAR；不要用长段落解释内部术语。

## 安全与状态表达

验证码只允许人工处理，不自动破解或绕过。

状态不确定、多候选、页面变化或结果不可确认时，页面和执行链路都应安全停止，并给出可查看的证据或下一步动作。

运行失败详情应按“结果、时间、执行阶段、通知、失败证据”分区。不要编造不存在的时间线或自动归因。

通知失败不能覆盖签到本身的真实结果。

## 验收清单

交付前按改动范围执行对应检查：

- 页面无横向溢出、遮挡、贴边和重复账号入口。
- 宽屏重心、移动端安全边距、浅色和深色主题都通过。
- 状态颜色和文案语义一致。
- 表单按钮与输入框间距稳定。
- 新增容器没有硬编码白底。
- 管理员、运营管理员和普通用户看到的导航差异符合权限边界。
- 不触发真实外部签到作为普通 UI 验收。
- 涉及自动执行、安全判断或容器部署时，按生产发布文档执行备份、健康检查和回退准备。

## 修改原则

小范围体验修复可以快速实施和发布，但仍要做与风险匹配的检查。修改登录页、主题、状态组件或响应式布局时，不要只凭单一截图判断完成。

当设计方向不明确时，优先保留现有业务结构，修正可感知问题；不要为了视觉重做引入大型 UI 框架、复杂动效或新的业务路径。
